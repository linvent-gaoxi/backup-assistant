# 开发过程回顾与版本管理

## 记录范围

本项目于 2026-11-04 建立 Git 仓库，将此前已经存在的源码、说明和演示材料按模块导入。首次导入的提交时间是整理时间，不代表各模块最初的开发时间。未保存的历史提交无法通过现有文件准确还原。

以下阶段根据现有源码、测试记录和项目迭代材料整理，不给无法核实的阶段指定日期或耗时。

## 开发阶段回顾

| 阶段 | 工作内容 | 可核对的项目材料 |
|---|---|---|
| 核心实现 | 目录树备份与还原、五类筛选、自定义归档、分块 Huffman、密码加密与完整性校验 | `src/`、`tests/tests.cpp`、格式与算法说明 |
| Linux 与网络服务 | Linux 构建、HTTPS 服务、客户端任务组件、远程部署与连接配置 | `linux/`、云端使用说明 |
| 账号与自动任务 | 邮箱验证码、注册登录、账号空间与配额、定时及轮询备份、回收站 | `linux/service.py`、`linux/cloud-client.py` |
| 桌面交互 | WPF UI 客户端、文件管理、多选拖选、上传下载弹窗与进度反馈 | `desktop-wpf/` |
| 功能补全 | Linux 文件系统语义、分块增量、归档目录与版本查询 | C++ 归档代码、网络服务和客户端代码 |
| 测试与演示 | 核心测试、集成检查、功能展示及实现说明 PPT | `tests/`、`docs/`、`演示材料/` |

阶段划分用于解释实现过程，不等同于已经存在的逐日开发日志。各项能力的适用平台与未验收范围以源码和测试记录为准。

## 本次仓库导入

导入按仓库规则、C++ 核心与测试、Linux 和网络模块、WPF 桌面模块、文档与演示材料划分提交。提交说明使用“导入现有”表述，避免把历史源码导入误读为当次新开发。

构建产物、临时演示构建目录、Python 缓存、备份归档、运行配置及密钥不纳入版本管理。已交付的演示 PPT 保留在仓库中。本地 Git 仓库尚未配置远程地址。

## 后续记录方式

- 每完成一个可说明的变更就提交，描述解决的问题和实际行为。
- 将运行环境、测试范围和失败结果记入相应文档。
- 使用真实提交时间。需要回顾之前的工作时，补充带依据的说明文档。
- 查看历史可运行 `git log --date=iso --pretty=fuller`，查看尚未提交的修改可运行 `git status`。

成员姓名和实际贡献需由项目组根据事实登记，仓库提交数量不能替代贡献说明。
