# 格式与算法说明

## 1. 文件格式

扩展名为 `.sbackup`，不是 ZIP。所有整数使用无符号小端序；字符串使用 UTF-8，以 `uint32` 字节长度开头，不带结尾零。清单路径长度限 1～32760 字节；根条目名称固定为 `.`，其余路径为相对路径，以 `/` 分隔。

### 1.1 未加密归档 SBKRAW01

| 顺序 | 字段 | 含义 |
|---|---|---|
| 1 | 8 字节 `SBKRAW01` | 格式与版本标识 |
| 2 | uint8 | 压缩模式：0 原始数据；1 分块 Huffman |
| 3 | 长度＋根目录名 | 还原时使用的原目录名，不含分隔符 |
| 4 | uint32 | 条目数，含根目录，1～1000000 |
| 5 | 条目序列 | 根目录优先，父目录先于子项 |
| 6 | 32 字节 | 之前全部字节的 SHA-256 |

每个条目包含：类型 `uint8`（0 文件，1 目录）、长度＋相对路径、修改时间 `uint64`（Windows FILETIME，UTC，100ns 自 1601 年起）、只读属性 `uint32`（0 或 FILE_ATTRIBUTE_READONLY）、原始文件大小 `uint64`（目录为 0）。

文件数据按不超过 1 MiB 的块连续写入，直到原始文件大小被完整消费。每块为：原始长度 `uint32`、存储长度 `uint32`、原始字节 CRC32 `uint32`、存储字节。空文件没有数据块。目录没有数据块。

模式 0 的块直接存原始字节；模式 1 的块第一个字节为子模式：

- `0`：其余字节为原始数据，长度应为原始长度＋1。
- `1`：紧随 256 个 `uint32` 字节频率，然后是 Huffman 位流；从高位到低位读取，最后不足一字节处补零。

根目录名及所有条目元数据均在整包 SHA-256 范围内。未加密 SHA-256 用于发现意外损坏，不构成对恶意修改者的身份认证。

### 1.2 加密封装 SBKENC01

| 顺序 | 字段 | 含义 |
|---|---|---|
| 1 | 8 字节 `SBKENC01` | 加密格式与版本标识 |
| 2 | 16 字节 | CSPRNG 随机盐 |
| 3 | 8 字节 | CSPRNG 随机 nonce 前缀 |
| 4 | 认证记录序列 | 完整的 SBKRAW01 归档分块加密 |

PBKDF2-HMAC-SHA256 迭代固定 200000 次，输入密码的 UTF-8 字节和随机盐，输出 32 字节 AES 密钥。固定参数属于版本 01，后续改变必须更新版本标识。

每条认证记录为 `uint32 密文长度`、密文字节、16 字节 GCM 标签。长度上限 1 MiB。记录编号从 0 开始；12 字节 nonce = 随机 8 字节前缀＋小端 `uint32` 编号。AAD = 完整 32 字节外层头＋小端编号＋小端密文长度。每条记录单独使用 AES-256-GCM；编号不允许回绕。

最后必须有一个长度为 0 且标签有效的终止记录，后面不得再有任何字节。这样可以发现数据截断、缺少结尾、块交换、头部修改或追加内容。每个备份使用新盐和 nonce 前缀。

## 2. 自行实现的算法

### 打包解包

递归收集目录和符合筛选的文件，按路径排序，写入根目录、条目和数据块。全部完成后添加整包摘要，必要时加密，最后通过同目录的 Windows 移动操作发布正式文件。正式文件存在时不替换。

### Huffman

统计当前块 256 种字节的频率；最小优先队列反复合并两个最小权节点。权值相同时按节点创建编号排序，保证编码端与解码端重建同一棵树。左边为 0，右边为 1。

单一字节块的树只有一个叶节点，其码字长度为零；频率表和原始长度足以还原。空块使用原始模式。只有“频率表＋编码字节”小于“原始模式字节”时才使用 Huffman，否则保存原始块。不同块独立编码，避免整文件载入内存。

### CRC32

自行实现标准反射 CRC32，生成多项式 `0xEDB88320`，初始值与最终异或值为 `0xFFFFFFFF`。标准校验向量 `123456789` 的结果为 `0xCBF43926`。

## 3. Windows 系统接口

- 密码算法、密钥派生、随机数和 SHA-256：`BCrypt*` 系列系统接口。
- 文件读取与写入保护：`CreateFileW`、`ReadFile`；备份读句柄仅共享读取，拒绝同时写入。
- 元数据：`GetFileAttributesExW`、`SetFileTime`、`SetFileAttributesW`。
- 结果发布：`MoveFileExW`，不设置覆盖标志。
- 界面：Win32 窗口、通用控件、文件对话框和 COM 文件夹选择器。

没有引入第三方压缩、打包或密码源码。AES 本身不是项目手写实现；答辩中应如实说明系统接口边界。

## 4. 还原顺序与错误处理

1. 检查输入文件和目标路径，拒绝重解析点。
2. 加密归档先逐块认证解密到临时文件，必须通过终止记录验证。
3. 验证完整的原始归档 SHA-256，再读取版本和清单。
4. 拒绝绝对路径、`..`、设备保留名、备用流、重复路径、父目录缺失和文件目录冲突。
5. 在目标目录内新建随机临时目录，逐块解码并检查 CRC32。
6. 文件写入完成后恢复文件元数据；目录元数据按从深到浅的顺序恢复。
7. 全部通过后，将临时目录移动为原目录名。失败时清理本次临时数据，不发布部分结果。

检查模式执行同样的解码和校验，只是不生成还原目录。解密临时文件仍会占用磁盘。
